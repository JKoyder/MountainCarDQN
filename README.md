This is my attempt to solve Gymnasium's Mountain Car problem using a DQN. Please check out my breakdown of the program here: https://www.youtube.com/watch?v=1O0WNJgrng4

This program uses a Deep Q-Network to solve the gymnasium MountainCar problem. In its current state, the program consists of three classes: BuildDQNModel, ExperienceReplay, and MountainCar. The BuildDQNModel class initializes the models used for training and testing. I used a three layer neural network for these models where the input layer neurons were equal to the state size of the environment, the hidden layer neurons were equal to 8, and the output layer neurons were equal to the action size of the environment.  The ExperienceReplay class was used for storing episodes in memory that could later be sampled for training. 

The MountainCar class was the primary class within the program. This class was responsible for all of the training and testing that the agent underwent. Starting with the train function, I opted to use a very large number of episodes to train the model. This is because the mountain car problem is not ideal for DQN training. The limited number of steps and the rarity in which the cart manages to reach the goal randomly are significant limitations that needed to be bypassed. To reach the goal and then train the agent to find the goal consistently I needed a large number of episodes. I instantiated and seeded the environment, established the hyperparameters to be used, and built the policy and target models using the BuildDQNModel class. The program then began iterating through each of the episodes.

On episode start, the current state, episode termination status, and the reward would be tracked. The program would then iterate through the steps until the episode was terminated, meaning the agent reached the goal or the number of steps exceeded 1000. Normally, mountain car is designed for 200 steps, however, using DQN prevented me from solving the problem within that limited number. Regardless of how many episodes, the agent could not reliably find the goal even once. This was the design decision behind increasing this number of steps to a greater, more forgiving number. For each step, the agent would take an action, either exploration or exploitation, and then append the state, new state, action, reward, and terminated values in memory. The state would then be set to the next state and the reward and step count would be incremented before continuing to the next step. If the action in the step is explorative, the agent will take a random action. If the action in the step is exploitative, the agent will take the best action given the policy model and current state. 

On episode completion, episode rewards are updated and whether the agent reached the goal is updated. If the agent reached the goal, a flag is set so that samples can be retrieved from memory, model optimization can occur, and exploration can begin to decay. I waited until this flag was set in order to boost performance; there is no need to sample episodes from memory if they do not contain a better reward. If the reward obtained from the last episode is greater than -200 and better than the previous greatest reward, the current models weights are saved to be used during testing.

The optimize function takes a batch of experiences from memory, stores the values for each of those experiences, and calculates q values based on the state and next state values. Each experience within the batch is then checked for the termination status. If the experience was completed, a flat reward is given. If the experience was not completed, a reward based on the next state is given. The policy model is then trained based on the reward given. 

Finally, the test function is used to test a model created with the saved weights obtained during training. This function creates a new neural network model, sets the weights of that model to that of the saved weights, and then iterates through the provided number of episodes. Unlike the train function, the agent always takes the best action at any given state. Reward is output so that the user can see what reward the agent gets with each episode.
